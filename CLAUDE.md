Working conventions for Claude Code
- At the start of each session, read SPEC.md and NEXT_SESSION.md.
- The project docs are split four ways:
  - SPEC.md: what the app is and the rules it follows (stack, grading, engine API, layers).
  - DECISIONS.md: decisions made along the way that the spec doesn't cover, oldest first.
  - BACKLOG.md: requested features and known bugs.
  - NEXT_SESSION.md: where things stand and what to pick up next. Update it at the end of each session.
- Keep timing logic out of the UI; keep the engine pure and tested.
- Don't change the tech stack, grading rules, or engine API without proposing the change and updating SPEC.md first.
- When a decision isn't covered in the spec, pick the simplest option, add an entry at the bottom of DECISIONS.md, and continue.
- New feature requests and bug reports go in BACKLOG.md. When a backlog item is done, remove it (or strike it through) and record any decisions in DECISIONS.md.
